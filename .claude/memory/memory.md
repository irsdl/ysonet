A contributor may keep unpublished notes in an untracked `private/` folder next to
this index. When `private/index.md` exists, read it as well; it is personal, so never
add its rows here.

Every file listed above is TRACKED and PUBLIC. So an entry must never NAME a private
artifact - a git-ignored path, dataset, folder, script, tool, gadget or plugin - not
even as a closing "the full detail is in X" pointer, which is the shape this goes wrong
in: the lesson is public, the pointer at the end of it is not. Describe the capability
generically and keep the name in `private/`. An entry that cannot be written without one
belongs in `private/` whole; if part of it is a reusable public lesson, write that part
as its own artifact-free entry. See `CLAUDE.md` -> "Memory Management" rule 0b and
"Public and private content (the seam)".
